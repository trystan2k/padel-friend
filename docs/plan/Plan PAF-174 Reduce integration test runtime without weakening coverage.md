## Chosen Approach

- Proposed solution: staged evidence-first optimization. Create durable proposal/boundary/measurement ledger, collect one authorized baseline, finish P1–P3 decisions before P4–P6, then one bounded implementation unit/commit per accepted proposal. Final before/after reconciliation reuses full delivery gate rather than rerunning green suites.
- Justification for simplicity:
  1. Chosen: narrow data preparation changes and reuse existing transactional SQL/cleanup/launcher seams. Smallest surface with direct correctness proofs.
  2. Alternative: consolidation-first to amortize worker/hooks. Potential benefit, but global-state leakage and test-order changes require deeper audits; consider only P5, after P1–P4.
  3. Rejected: new persistent fixture service, broad concurrency increases, global trigger suppression, altered planner policy or skipping restore coverage. Larger risk or violates explicit boundaries. No new dependencies expected.
- Components to be modified/created: sole artifact written by planner is this plan. Implementation agents create/update `docs/plan/PAF-174-findings.md`; conditionally modify proposal scopes listed below and colocated existing tests/declaration contracts. Retain integration partition/config/workflow unless specific accepted change needs them. No unrelated refactors.
