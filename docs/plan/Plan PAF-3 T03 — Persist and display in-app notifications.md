## Chosen Approach

- Proposed solution: New generic notifications and notification_preferences stores. Database AFTER triggers observe committed domain transitions and call a private idempotent insertion function within the same transaction. Recipient-only SELECT policies; explicit RPCs for read mutations/preferences and invitation-ID acceptance. Server functions authenticate via getClaims(), validate input and return allowlisted DTOs. Load/focus/visibility/online refresh, no subscriptions. Center owns paginated rows plus authoritative whole-store count; dashboard header exposes badge. Dedicated notification detail resolves targets at request time and safely handles invitations, inaccessible or gone targets.
- Justification for simplicity: Considered (1) application-side notification writes: rejected because current invitation writes and governance RPCs would split atomicity and require compensation; (2) outbox/worker/event bus/Realtime: rejected as unnecessary delivery infrastructure and T16/T17 scope; (3) transactional triggers plus restricted insertion helper: chosen, minimal mutation blast radius and no crash gap. Generic store uses typed identifiers, not arbitrary URLs, localized prose or unbounded JSON. No preference suppresses required in-app alerts.
- Components to be modified/created: Four migrations specified below; generated src/lib/supabase/database.types.ts; src/features/notifications/*; thin protected route adapters; dashboard header integration; en/pt-BR/es translations; test/notifications.*.test.{ts,tsx}; e2e/notifications.spec.ts. Generated route tree only through normal router generation; never hand-edit it.

### Database contract — exact migration filenames and SQL shape

All new functions: schema-qualified relations/functions, SECURITY DEFINER SET search_path = '', no dynamic SQL. Authenticated entrypoints reject null auth.uid() or anonymous JWT with 28000; errors expose no private row details. Revoke function EXECUTE from PUBLIC, anon, authenticated immediately on creation; grant authenticated only for entrypoints listed. Trigger/helper functions have no browser-callable EXECUTE. Every migration unit applies locally, runs pnpm db:types, commits generated types and passes pnpm db:types:check. Filenames reserved after current latest 20261015123420; confirm no collision before execution, coordinate rather than silently renaming.

**1. supabase/migrations/20261015180000_notifications_store.sql**

- public.notifications:
  - id uuid PRIMARY KEY DEFAULT gen_random_uuid().
  - recipient_user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE.
  - event_key text NOT NULL CHECK (char_length(event_key) BETWEEN 1 AND 240).
  - kind text NOT NULL CHECK (char_length(kind) BETWEEN 1 AND 80). Deliberately extensible; supported community kinds validated by producer, unknown future kinds render generic copy without an action.
  - category text NOT NULL CHECK (category IN ('community','matches','results','rankings','leagues')).
  - target_type text NOT NULL CHECK (char_length(target_type) BETWEEN 1 AND 80); target_id uuid NOT NULL; community_id uuid NULL. Domain identifiers intentionally have NO foreign keys: deletion never erases alert or mutates identity/idempotency comparison. They are not authorization proof.
  - created_at timestamptz NOT NULL DEFAULT now(); read_at timestamptz NULL.
  - CONSTRAINT notifications_recipient_event_key UNIQUE (recipient_user_id,event_key).
- Index notifications_recipient_created_idx ON (recipient_user_id,created_at DESC,id DESC); partial notifications_recipient_unread_idx ON (recipient_user_id,created_at DESC,id DESC) WHERE read_at IS NULL.
- ENABLE RLS; REVOKE ALL ON TABLE from anon,authenticated; GRANT SELECT of all above columns to authenticated only. Policy notifications_read FOR SELECT TO authenticated USING (recipient_user_id = (SELECT auth.uid()) AND (SELECT auth.uid()) IS NOT NULL AND NOT coalesce((auth.jwt()->>'is_anonymous')::boolean,false)). No member subquery and no INSERT/UPDATE/DELETE policies/grants.
- public.persist_notification(p_recipient_user_id uuid,p_event_key text,p_kind text,p_category text,p_target_type text,p_target_id uuid,p_community_id uuid) RETURNS uuid. Private helper only. INSERT ... ON CONFLICT ON CONSTRAINT notifications_recipient_event_key DO NOTHING RETURNING id; on conflict SELECT existing row and compare immutable semantic columns with IS DISTINCT FROM (kind,category,target_type,target_id,community_id). Exact match returns original ID without changing created_at/read_at; mismatch raises 23505 'NOTIFICATION_EVENT_CONFLICT'. Do not use DO UPDATE or swallow mismatch. Read timestamps excluded from equality. Test two concurrent helper invocations under READ COMMITTED plus retry after already-read. Calling helper as authenticated must fail. Trusted trigger supplies recipient and event key; no client-supplied recipient/event.
- public.mark_notification_read(p_notification_id uuid) RETURNS timestamptz: UPDATE own row SET read_at=coalesce(read_at,now()) RETURNING read_at; absent/not-owned raises identical 42501. Idempotent; no existence oracle.
- public.mark_all_notifications_read(p_before timestamptz) RETURNS bigint: require nonnull p_before <= transaction_timestamp(); UPDATE own unread rows WHERE created_at <= p_before; return affected count. Client uses server snapshot time, never client wall-clock. Rows arriving later remain unread. Returned mutation count is NOT unread count.
- public.count_my_unread_notifications() RETURNS bigint: authenticated check then recipient-scoped COUNT(*) WHERE read_at IS NULL. No membership condition; removals must remain visible. Grant authenticated EXECUTE for these three entrypoints only.

**2. supabase/migrations/20261015180100_notification_preferences.sql**

- public.notification_preferences: user_id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE; push_enabled boolean NOT NULL DEFAULT false; push_community, push_matches, push_results, push_rankings, push_leagues boolean NOT NULL DEFAULT true; critical_in_app_enabled boolean NOT NULL DEFAULT true CHECK (critical_in_app_enabled); updated_at timestamptz NOT NULL DEFAULT now(). No category-level in-app suppression field.
- ENABLE RLS; same nonanonymous owner-equality SELECT policy and column SELECT grant; no direct write grants. No backfill needed: missing row means defaults, GET is read-only.
- public.set_my_notification_preferences(p_push_enabled boolean,p_push_community boolean,p_push_matches boolean,p_push_results boolean,p_push_rankings boolean,p_push_leagues boolean) RETURNS public.notification_preferences. Reject null arguments, authenticated check, INSERT ... ON CONFLICT(user_id) DO UPDATE the six booleans and updated_at, always critical_in_app_enabled=true. Entire explicit form snapshot is last-write-wins; no recipient parameter. Grant authenticated EXECUTE only here. Preferences never consulted by membership/invitation in-app producer.

**3. supabase/migrations/20261015180200_community_notification_producers.sql**

- public.notify_community_invitation() RETURNS trigger, private. AFTER INSERT ON public.community_invitations FOR EACH ROW trigger community_invitation_notification. For valid new invitation with nonnull invitee, not redeemed/revoked and expires_at > now(), persist recipient NEW.invitee_user_id, event_key 'community.invitation:' || NEW.id::text, kind 'community_invitation', category 'community', target_type 'community_invitation', target_id NEW.id, community_id NEW.community_id. Existing invitation creation RLS/admin checks remain source of authorization. No actor notification, token/token_hash, inviter profile, email, settings, role or invitation secret enters new table.
- public.notify_community_membership() RETURNS trigger, private. AFTER UPDATE OF status ON public.community_members, only actual status change. OLD.pending -> NEW.active: event 'community.membership_approved:' || NEW.id, kind 'community_membership_approved'. OLD.pending -> NEW.inactive: event 'community.membership_denied:' || NEW.id, kind 'community_membership_denied'. OLD.active -> NEW.inactive only when auth.uid() IS NOT NULL AND auth.uid() <> NEW.user_id: event 'community.membership_removed:' || NEW.id, kind 'community_membership_removed'. Recipient NEW.user_id, category community, target_type 'community_membership', target_id NEW.id, community_id NEW.community_id. No self-leave alert, no self-join alert, no role-change alert, no speculative admin fanout. Each membership interval can undergo each transition once; reactivation creates a new interval ID, hence a distinct legitimate future approval/removal event.
- No trigger backfill of historical mutations, no changes to existing community_notifications. Domain retry may retain existing error semantics (INVITATION_ALREADY_OPEN / invalid transition); requirement is no additional alert, not changing all mutation APIs to successful replay. Reconnect only reads. Insert failure aborts original domain mutation: required durable alert cannot silently disappear.

**4. supabase/migrations/20261015180300_notification_targets.sql**

- public.get_my_notification_target(p_notification_id uuid) RETURNS TABLE (target_status text,community_id uuid,community_name text,invitation_id uuid,membership_status text). Check ownership before resolving anything. Foreign/missing notification raises identical 42501. Unknown kind, missing community/domain row, expired/revoked invitation, invalid visibility or no-longer-authorized target -> exactly one row ('unavailable',NULL,NULL,NULL,NULL), never exception from a missing join.
- Invitation resolution requires invitation.id=notification.target_id AND invitee_user_id=auth.uid() AND matching community_id and private community, valid/unrevoked/unredeemed and not currently open/inactive membership that would block acceptance. Return 'invitation_available', authorized community id/name and invitation_id, null membership_status. Recipient binding is explicit permission for this limited disclosure; never return token/hash or other invitees. A redeemed invitation returns 'membership_available' only if caller now has current authorized membership; otherwise unavailable.
- Membership resolution requires matching membership ID, user and community. Return 'membership_available' with current active membership and nonarchived/existing community only when existing domain access rules allow it; stale interval is not proof of current access. If no access, return unavailable without community name. Removed/denied alerts themselves remain readable with generic localized body. Use existing schema's archive/access semantics; if no archive column exists do not invent one—missing or private-inaccessible targets are already unavailable. No membership joins in RLS policy.
- public.accept_my_notification_invitation(p_notification_id uuid) RETURNS TABLE (community_id uuid,status public.community_membership_status). Auth/owner/kind verification first, then lock invitation row derived from notification, not arbitrary client-supplied invitation ID. Repeat every existing accept_community_invitation eligibility check (recipient, private community, revoked, expiry, redeemed, open/inactive membership), locking and constraint/error mappings; insert membership and mark invitation redeemed in one transaction. Preserve existing token RPC unchanged; do not generate/expose a replacement token. If already redeemed, return existing matching membership result for same recipient when it exists; never create a second interval. Refresh target/read state after action; successful acceptance does not need another alert for instant self-join. Reuse existing membership trigger for later admin approval.
- Grant authenticated EXECUTE only for these two entrypoints. Tests must demonstrate no ID-based bypass of recipient checks and parity of token-vs-notification redemption eligibility.
