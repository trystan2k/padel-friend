## Chosen Approach

- Proposed solution: Thin public TanStack file route with a single optional authenticated-state boolean from verified server claims. Render one localized, tokenized page with variant CTAs: guest gets `/login` and `/onboarding/account`, authenticated visitor gets `/dashboard`; both get the same public body and `/privacy`/contact footer. No redirect from `/`, never read player profile or onboarding RPCs there, and never serialize identity data. Clicking `/dashboard` uses the existing onboarding/protected gate. Preserve existing sign-out and identity-teardown outcomes by making their existing full-document navigation target `/login` directly; don't route home by testing cookies or referrers around logout.
- Justification for simplicity: An entirely auth-agnostic page avoids a server call but fails the verified signed-in composition; reusing `getOnboardingStatus` adds profile/password/claim reads and can turn unrelated private-data failures into homepage failures. A boolean loader fits SSR without client flash, session subscription, or another auth context. A separate static landing bundle would duplicate locale/theme handling and split the same hostname unnecessarily. Preserve public path contract with typed links; no new dependencies, global layout framework, schema, RLS, or auth-flow redesign.
