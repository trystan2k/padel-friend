## Chosen Approach

- Proposed solution: **Probe first; conditionally prefer pinned CLI + oxfmt with a generated-file-only formatter override.** Run the current committed-file oxfmt probe and a fresh generated-file probe using an unignored scratch path. If ordinary oxfmt already preserves the baseline apart from real schema additions, set `db:types` exactly to `"pnpm exec supabase gen types typescript --local --schema public,storage,graphql_public > src/lib/supabase/database.types.ts && pnpm exec oxfmt --write src/lib/supabase/database.types.ts"`; remove the file's ignore entry. If ordinary oxfmt changes existing style, first test a `.oxfmtrc.json` override for `src/lib/supabase/database.types.ts` with `semi: false`, `singleQuote: false`, `trailingComma: "all"` (retain global settings), remove its ignore entry, and use the **same script**. Select this override only if the formatted committed baseline is unchanged or residual old-schema churn stays within the gate and generated output is stable. If override still causes excessive unrelated churn or fails to preserve semantic output, use the CLI's dense output as canonical: exact script `"pnpm exec supabase gen types typescript --local --schema public,storage,graphql_public > src/lib/supabase/database.types.ts"`, keep existing ignore entry, **do not** add the override; report the measured gate violation and obtain approval before proceeding. Another formatter/custom postprocessor is a last resort only if it demonstrably preserves baseline with fewer changed lines; no new tool unless the pinned oxfmt route fails.
- Justification for simplicity: Two already-installed executables, one script, one generated file, at most one targeted formatter override. Avoid manual edits to generated output, global formatter reconfiguration, new dependencies, custom generator wrappers, CI/consumer changes, or changing migrations. Brainstormed alternatives: (A) default oxfmt: smallest config change if baseline survives; (B) scoped override: best chance to retain legible committed style and keep PR below gate; (C) dense CLI canonical: guaranteed CLI-format path, but historical 1,238-line churn alone exceeds gate. Choose A/B using probes rather than assuming either succeeds. Keep global `format:check` and lint-staged oxfmt consistent with chosen output.
- Components to be modified/created (exact expected list for formatted route: **four files**):
  - **CHANGED** `package.json` — only `db:types` script, exact generator-plus-formatter command above; no lockfile change.
  - **CHANGED** `.oxfmtrc.json` — remove only `"src/lib/supabase/database.types.ts"` from `ignorePatterns`; add a single `overrides` entry with `files: ["src/lib/supabase/database.types.ts"]` and `options: { "semi": false, "singleQuote": false, "trailingComma": "all" }` **only if probe requires and validates it**. Check pinned oxfmt accepts the override by running it; do not alter global options.
  - **CHANGED (generated)** `src/lib/supabase/database.types.ts` — full local schema output: existing public/storage/graphql_public types plus PAF-26 community tables, enums, and callable RPC types; no hand edits.
