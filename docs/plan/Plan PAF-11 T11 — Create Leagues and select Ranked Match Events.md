## Chosen Approach

- Proposed solution: Five coherent vertical units, sequential on existing branch: **U1 League creation/lifecycle → U2 Ranked publication/admission → U3 changes/reconfirmation → U4 actual-play eligibility + provisional-safe counters → U5 cross-flow acceptance/visual verification**. Provisional support, translations, accessibility and owning tests ship in relevant units, not as a late retrofit or final polish-only child.
- Justification for simplicity:
  1. **Chosen — extend authoritative SQL commands and existing React flows.** One eligibility vocabulary, one explicit event association, same lock/consent/idempotency contracts. Narrow read-time counter aggregation avoids adding an unnecessary projector/queue alongside T10.
  2. **Rejected — UI-only Ranked state or computed active-League association.** Tamperable, retroactively changes old events, misses invitation/approval/actual-group paths and violates AC2/3/6.
  3. **Rejected — generic League workflow engine, second rating system, separate provisional workflow, asynchronous standings infrastructure.** More services/states/retries without needed behavior. Full T12 UI is not needed to prove narrow AC12 counters. Splitting provisional eligibility into separate late unit would leave U2/U3 knowingly incompatible with accepted amendment.
- Components to be modified/created: New `src/features/leagues` domain/validators/DTOs/functions/StyleX/UI; thin protected community League routes; forward-only migrations after `20261101152000`; generated database types; existing matches publication/admission/edit/result contracts/components; notification DTO/copy where needed; locale JSONs; fixture builders/cleanup; League and Ranked unit/integration/E2E suites and real Pencil reference manifest. No new npm dependency planned.

### Shared implementation contracts

**Durable association.** Prefer `match_events.league_id nullable` as single source of truth (`null` = Unranked). DTO may expose derived `competition_status`; do not add independently mutable boolean that can disagree. SQL check forbids nonnull association on Friendly. Same-community composite FK `(league_id,community_id)` references League `(id,community_id)`. Cross-row period/existence/lifecycle checks occur inside locked commands and protected mutation guards. If approved UI contract requires explicit boolean, constrain exact equivalence with nullable association. New Competitive draft: no candidate → Unranked; one candidate → Ranked + displayed explicit candidate; several → Ranked intent but **no selected ID**, publication blocked until selection or opt-out. User's deliberate Unranked choice survives option reloads, retries and schedule/type changes; never reset it silently. Friendly publishes null only.

**Eligibility helpers.** Separate target predicates from actor privileges: (a) current active community membership for admission, (b) historical activated interval at played_at, (c) same-community League window and existing-at-publication check. Historical predicate: `activated_at IS NOT NULL AND activated_at <= played_at AND (valid_until IS NULL OR played_at < valid_until)` on an interval known to have activated, including now-inactive rows; use valid_from consistency checks too. Never reject historical play solely because member is inactive today. Provisional flag does not enter target eligibility. No auth session/claim requirement for a target provisional player. New actor RPCs still call assert_actor_not_provisional and existing session-revocation checks.

**Admission inventory.** Cover publish creator auto-registration + initial invitees, ordinary request/direct join/re-entry, organizer request approval, invitation creation/resend/acceptance, add-by-name/email registered/provisional/new branches, and any internal registration primitive used by them. Ranked denied to nonmembers before persistence; pending out-of-level **members** still use existing approval rules. Rank switch evaluates actual membership, not immutable historical `source='guest'`: guest who genuinely became active member may qualify. Existing pending nonmember requests/invites must be explicitly resolved/denied or made non-actionable; never allow later acceptance after switch. No new email-existence oracle.

**Consent.** League-ID change is major even if both choices are Ranked. Rank flip or schedule change requiring consent increments generation once per effective edit, carries audit before/after League/status/period impact, and updates registrations **and current attempts** atomically. Follow existing creator consent convention; at minimum any accepted player other than creator triggers AC7. **Approved intake decision to document: provisional players cannot reconfirm; automatically carry over rather than block.** At each affected edit set their required_generation and confirmed_generation to new generation together; preserve accepted_order, current attempt, capacity and accepted_at; distinguish system carry from user reconfirmation in audit. Registered participants remain paused until explicit reconfirmation/withdrawal/cutoff. Claim does not retroactively create consent debt. Provisional removed from membership still cannot become Ranked-eligible merely through carry-over.

**Period changes.** Validate merged starts_at + League association in one edit. Outside selected period: reject partial edit, show selected League/window and lost impact; user chooses valid reschedule or explicit Unranked patch. Never automatically switch League or status. Closure after booking never rebinds event; closed League remains valid historical association for actual play inside effective window. New out-of-window play is rejected even if scheduled instant was eligible.

**Atomic results/global independence.** Extend latest shared fact validator and confirmation seam. Validate every actual participant, not invitees/accepted/reserve summaries; all-four gate fails whole Ranked group, never silently excludes just invalid player's counter. Confirmation recheck uses historical play membership and current effective League boundary, including manual close after proposal submission. Invalid changes must produce visible blocked/resolution state, including scheduler failures, not vanish from queue. Keep existing rating projector invocation and lock/prelock protocol unchanged; League choice never filters Unranked out of global rating.

**Minimal counters for AC12.** Read-only authorized RPC aggregates immutable confirmed ratable Competitive facts whose parent explicitly references League, whose actual quartet passes membership/window eligibility, by permanent user UUID. Return Matches/W/L/D/Sets Won/Lost/differential; active eligible members may have zero rows/counters and historical earned participants remain visible. No mu, global level, reliability or delta as initial/order input. Claim changes display marker only; no participation migration or counter write. Current provisional badge comes from profile, never email/inviter. U4 owns this real behavior and tests; T12 can reuse it. Full position/tie/award/history UI not implied by a counter reader.

**Locking/security.** Reuse community lock as outer serialization boundary for settings/League lifecycle/event commands, then League rows (UUID order) before event/registration/proposal paths where needed. Re-entry through existing event helper is safe only with same outer community held. Read-only counter query takes no global rating lock. Do not acquire League/community/event locks after global rating lock. Inspect finalizer's effective prelock graph before edits; use concurrent real DB connections to prove no deadlocks. Internal helpers revoked from browser roles; RLS and restrictive provisional/revoked policies explicitly protect new tables. GETs remain read-only; effective lifecycle reads cannot secretly mutate via stable SQL function.
