## Privacy and guard coverage

The plugin appends only schema version, timestamp, randomly generated opaque per-session correlation, fixed event and tool category, outcome and measured elapsed milliseconds to `.opencode/state/delivery-telemetry.jsonl`. Session IDs are provided by V2 tool hook context, retained only in a bounded in-memory map (512 entries), and never persisted; map eviction can issue a new correlation for a later event in that session. It does not store tool inputs, paths, output, prompts, session IDs, errors, approvals, URLs or source. It does not upload or delete records. Existing telemetry remains untouched when unsafe permissions prevent appending; I/O failure drops records with a fixed notice. Storage requires owner-only state directory and file and rejects symlinks and nonregular or multiply linked files. UID ownership checks use `process.getuid` when available; on runtimes without it, telemetry ownership validation fails open by dropping telemetry, while guards remain active. Remove the plugin to opt out; manually delete the telemetry file only if its owner chooses. The file can grow indefinitely.

Native permissions remain authoritative. For covered `edit` operations, missing agent identity, empty target lists, unresolvable targets, and canonical targets outside the checkout are denied. Existing targets resolve through `realpath`; missing targets resolve through their nearest existing realpath ancestor plus remaining path components. Delegation also denies missing agent identity or empty targets. The hook denies reviewer edits, frozen skill edits, planner/log edits outside their respective document folders, unknown delegated IDs, and all child delegation. Explicit native denies do not reach the hook. Canonical resolution narrows symlink escapes, but a filesystem race remains between checking a path and the native tool's later write; hard-link aliases are not detected. On coordinator `execute.before`, shell commands matching the explicit mutating denylist are denied: output/append redirections and `tee`, `sed -i` including suffixes such as `-i.bak`, `rm`/`mv`/`cp` with repo-relative-looking paths, and `git commit`, `git checkout --`, `git reset --hard`, or `git clean`. This is not shell parsing or complete containment: quoted redirect metacharacters may false-positive (e.g. `git log --grep='a > b'`); the coordinator routes such commands to specialists. Unmatched/unknown commands, absolute-path targets outside those patterns, shell indirection, MCP, and Code Mode pass through to native policy. The notice directs repository mutation to sanctioned file tools or git-specialist. Guards fail closed only for these covered checks; uncovered operations remain governed by native policy. Plugin absence/load failure removes supplemental guards. Tool duration counts are partial, bounded, and not phase timing or token/cost accounting. Runtime behavior has not been tested.

## Session and tool optimizations

- The title hook derives a deterministic title from the first user message's text in the title request, skipping leading whitespace before taking its first line, stripping heading markers/backticks and collapsing whitespace, capped at 60 characters. Missing text yields `Delivery session`; no auxiliary model call is needed. The request exposes `messages`, not a dedicated initial-prompt field, so the first user message is the available approximation. Titles are OpenCode session-local metadata, not telemetry storage; prompt-derived titles may contain user text.
- The context hook removes `write` and `edit` tool schemas for code, architecture, UX and QA reviewers, not dev-log. This strengthens enforcement and saves schema tokens; native permissions remain primary.
- Direct `harness` tools use explicit per-tool permission actions and executor assertions, not Code Mode. The coordinator and all eleven specialists may call `harness_context_bundle`; only the coordinator and QA may call `harness_telemetry_summary`. Executor role checks add defense in depth. The bundle returns current branch, changed-file `path` and `status`, skill IDs and generation time. V2 VCS and skill responses wrap results in `data`; status exposes `file` and change `status`, not staging information. Neither tool returns source or raw telemetry. The summary uses the writer's hardened checks and bounded reads to select the newest at most 100,000 complete lines within the latest 32 MiB, skipping partial boundary lines and lines over 64 KiB. `window` reports included line count, starting byte and truncation; `scannedLines` and `scannedBytes` report the forward scan. Missing/unsafe files fail soft. Calls honor cancellation. Native permissions remain authoritative.
- Hook-level reasoning-effort overrides are skipped: selected variants live in frontmatter (see model inventory above), while bare model identifiers retain provider defaults. Deterministic titles remove the auxiliary title call.

Runtime probes supplied by the user found that a `subagent`-action grant in a subagent-mode file prevents its registration, while primary-agent grants register. Do not add such grants to subagent frontmatter. Subagent-mode agents have no delegation tool in this runtime, so the former implementation-to-testing exception is moot: only the coordinator delegates. Implementers run browser checks through ask-gated shell or return those needs to the coordinator.
