## Notes

- No critical findings were raised by any of the three reviewers.
- F1 residual (documented in `docs/community-admin-expansion.md`): the object `Content-Type`/MIME metadata is client-supplied, so a determined Admin can still submit mislabeled bytes through a direct RPC call. Mitigated by the private bucket, the JPEG/PNG/WebP extension allowlist (no SVG/HTML execution) and 60-second signed URLs with `no-store`; a genuinely trusted byte-verification boundary is not available without a service-role path, which this project forbids. The DB layer now enforces owner, exact path, size, MIME/extension consistency and current-Admin scope.
- The fix loop ran 3 iterations, one more than the 2-iteration cap, because iteration 2 introduced a Members-screen geometry regression (`memberCardGeometry`, 30px) that had to be corrected rather than left on the branch. That regression is fixed and all six visual residuals are back under budget.
- F23 is deferred: converting the stale-response test into a component test with controlled out-of-order responses is beyond the "trivial fix" threshold for this delivery.
- F24 and F25 came from the Copilot review on the pull request (both Medium). F24 replaced the loose invitee UUID pattern with the strict pattern used by the other community validators, plus a regression test. F25 replaced the per-notification timezone RPC fan-out with a single batched RPC (`20261015123420_community_notification_timezones_batch.sql`), reducing an inbox page from up to 51 round trips to 2.
- PAF-48 completion: the six Linux residuals were captured from green CI run [38734384958](https://github.com/trystan2k/padel-friend/actions/runs/38734384958) at SHA `552c672`, and are recorded as measurements in `docs/visual/community-admin-residuals.md`. The Members screen (`wFqGR`) passes with only 65px of headroom (99.6% of budget consumed) — flagged as a flakiness risk; the budget was deliberately **not** widened.
- Open follow-up recorded in the residuals document: CI uploaded only `coverage/` HTML because `test-results/` is empty when every E2E test passes, so the per-screen residual JSON/PNG attachments are not retained. A dedicated artifact directory (or `if: always()` retention) is the tracked improvement.
- F26–F28 came from a second Copilot review pass on the pull request. F26 gated the discoverability confirmation on a real successful save (it previously also rendered on initial mount, announcing a save that never happened through `aria-live="polite"`). F27 removed a dead `timeZone` prop, supplied the required `time_zone` on every inbox fixture and added assertions on the exact rendered timestamps. F28 moved an inline 44px target into the StyleX block with space tokens.
- **Newly discovered gap (not fixed here):** `tsconfig.json` includes `test/**/*.ts` but **not** `test/**/*.tsx`, so the `.tsx` test files are never type-checked — which is exactly how F27's dead prop and missing field escaped. Enabling the include surfaces **15 pre-existing type errors** in `test/community.admin-ui.test.tsx` (TS2322 at 142, 477, 628, 685, 903, 915; TS2345 at 500; TS2322 at 637 for `Element` vs `HTMLElement`; TS2339 at 748, 1115 for `value`) and `test/community.onboarding.test.tsx` (TS2339 at 194–197; TS2322 at 228). The include was therefore reverted; closing this gap is tracked as a follow-up.
