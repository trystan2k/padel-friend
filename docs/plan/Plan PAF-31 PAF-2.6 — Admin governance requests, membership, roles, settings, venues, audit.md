## Chosen Approach

- Proposed solution: **A: narrow definer RPC for transactional membership transitions; RLS direct writes where already permitted; narrow definer read RPC for admin-only named roster; existing audit triggers stay authoritative.** Reject (1) all client-direct membership UPDATE: hard to return explicit final-Admin/transition errors, cannot reactivate an inactive row, and concurrency deserves one transactional boundary; reject (2) general service-role application admin/repository layer: bypasses RLS, duplicates SQL invariants and increases key exposure. Reject a single mega admin RPC or broad definer views: increases privilege/projection risk. Brainstormed edge cases: pending denial vs formerly active member, instant close before `valid_from`/`activated_at`, concurrent demotions of two Admins, demoted actor trying another request, duplicate invite including expired-but-open token, invalid invitee UUID, cross-community row IDs, archived venue referenced by history, malicious search wildcards, stale UI after mutation, private data in SSR/logs, locale expansion, and example Pencil data not backed by schema.
- Justification for simplicity: One transition RPC `govern_community_member(p_community_id uuid, p_membership_id uuid, p_action text)` with six **fixed** actions (`approve`, `deny`, `remove`, `reactivate`, `promote`, `demote`) reuses PAF-26 constraints and triggers; _do not_ permit arbitrary field patches. Exact actions get dedicated server-function exports for call-site clarity. Existing RLS UPDATE handles settings; RLS INSERT/UPDATE handles invitations and venue create/edit/archive. One purpose-built `search_community_members` definer function addresses profile owner-only RLS without widening global profile policies. Scope audit to current four entities; never synthesize unsupported events/content. Public-facing functions use `createServerFn({method:'POST'|'GET'}).validator(...).handler(...)`, `requireAuthenticatedClient()`, controlled projection and stable error codes; database remains final authority (server-side preflight alone insufficient).
