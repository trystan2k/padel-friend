## Chosen Approach

- Proposed solution: Thin route adapters, focused src/features/home slice with bounded server-authoritative composition, URL-backed selected-community context, reusable visible/online refetch lifecycle for mounted authorized surfaces, existing transactional commands for all writes, existing job stores for diagnostics and failure alerts.
- Justification for simplicity: Compared (1) a query-cache/event-bus/WebSocket architecture: introduces framework, RLS publication/authorization and lifecycle surfaces absent today; rejected. (2) separate polling in every component: fastest initial patch but overlapping fetch storms, cleanup gaps and inconsistent identity handling; rejected. (3) shared scoped refetch lifecycle plus existing readers/controllers: chosen. PRD §45 explicitly permits technology choice and intake accepts subscriptions/refetch. No Supabase Realtime channel needed: every refetch rechecks getClaims/RLS. This is periodic refetch convergence, not a claim of push/WebSocket delivery. Start visible-online polling at 3s, single-flight/coalesced; engineering acceptance target ≤5s under normal local/representative load, excluding genuine outage. Validate request volume/performance in U4. Do not replace this with unprotected table subscriptions for lower latency.
- Components to be modified/created: Existing dashboard and affected protected routes; proposed home/{HomeDashboard.tsx,home.functions.ts,home.server.ts,home-contracts.ts,home.validators.ts,home.styles.ts}; selected-community control under community (shared only where reused); proposed src/lib/use-authoritative-refresh.ts and small pure lifecycle helper if needed; existing feature controllers/NotificationBadge/League refresh adapter; scoped auth/cache/SSR changes; server-only diagnostics module, operational scripts/runbook, additive migrations/generated types when needed; locale files; test/home.*, test/realtime.*, test/release-integrity.* and e2e Home/convergence/security/a11y/full-loop coverage. Proposed names are implementation expectations, not assertions files already exist.

If multiple active Leagues exist, choose via explicit deterministic selector consistent with current League options; never imply arbitrary first League is only League. Read movement from committed history, use translated unavailable/new-entry state when no prior point, never manufacture delta. No eligible ranking gives useful empty state with existing links.
- Refresh contract: scope identity = authenticated user + community/event/League + mounted view. Start after hydration; no server timers/global private state. One in-flight refresh per mounted scope, coalesce bursts with at most one trailing request, discard stale generation results, cleanup timers/listeners on unmount/scope/auth change. Pause offline/hidden, immediate refresh on online/focus/visibility return, bounded backoff on repeated errors with explicit stale status, restore normal cadence after success. - Writes: no optimistic Playing assignment, result confirmation, rating or League close. Existing RPC locks/version/status/attempt identities remain authority. Do not auto-replay a stale approval against latest version; preserve draft safely when another result supersedes it. Network loss after submit is outcome-unknown, refetch before retry; use existing idempotency identity, never blindly new write.
- Cache boundaries: private/no-store on authenticated SSR, loader/server-function responses, auth redirects/errors; preserve Set-Cookie PKCE behavior. Workers/CDN must not cache these responses. Router loader and component state retired on signout/account switch; request-local i18n remains factory-based across concurrent SSR.
