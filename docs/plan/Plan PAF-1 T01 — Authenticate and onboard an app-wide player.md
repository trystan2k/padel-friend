## Task Analysis

- Main objective: PAF-1 / T01 — Authenticate and onboard an app-wide player. Keep Google OAuth/PKCE **and** email/password; block all authenticated-but-unonboarded users from protected content; persist exactly one app-wide sporting profile and initial rating per identity; render/edit permitted profile fields and avatar on `/dashboard`. Single Linear work item, existing branch, one commit at end. PAF-1 has no dependencies; blocks PAF-2 and PAF-3.
- Identified dependencies: Existing TanStack Start request-scoped Supabase SSR clients, `/auth/callback` cookie forwarding, `getClaims()` per private server function, Supabase local DB/Storage, StyleX/Base UI, three JSON locales, Pencil frames `EGb2g` (account), `PdRtP` (player setup), `vARtQ` (player profile), `n6zFq` (states), and `pnpm complete-check`. Relevant PRD: §§10–12, 25, 47.2–47.3, 54–55. **Preflight design discrepancy:** `design-tokens/dist/tokens.css` currently has blue starter palette, only 8/16/32px spacing and no typography variables; Pencil specifies green palette, Inter/Manrope, 3–18px spacing and 9–20px radii. Exact faithful implementation cannot use existing tokens alone. Obtain user/design-owner approval for updating existing token values and adding only indispensable missing token definitions, or approved changes to Pencil. Do not silently hardcode values or claim current tokens match. No separate profile-edit Pencil frame exists; adapt player-profile frame `vARtQ` into dashboard edit state, seek design review before implementation.
- System impact: New transactional SQL migration, restricted RLS/Storage, private server functions, auth redirects/guards, onboarding/dashboard UI, generated database types, token reconciliation, translations, tests; remove scaffold notes code/UI. No community model or rating progression. High-risk: SSR cookies, open redirects, untrusted rating writes, avatar object ownership, leaks from auth identity.

## Chosen Approach

- Proposed solution: Retain both current sign-in methods and cookie-aware server client. Use one small `SECURITY DEFINER` PostgreSQL onboarding RPC (claims-derived user ID, atomic profile+rating creation, no overwrite on retry); ordinary profile edits use column-limited owner update; rating has owner SELECT only and **no client INSERT/UPDATE/DELETE**. Direct browser Supabase Storage upload uses authenticated JWT and owner-path RLS; server function finalizes verified avatar object key and issues short-lived owner-only signed read URLs. Check claims and profile completion in server guards/functions, not just UI. `/onboarding` is independently guarded; `_protected` checks completed profile. No service-role key in Worker/browser.
- Justification for simplicity: Option A, two client-side inserts, risks orphan ratings and user-forged rating fields; reject. Option B, trigger on `auth.users` plus extra status table/session middleware, creates unfinished profiles on registration and more moving parts; reject. Chosen RPC provides one transaction and replay-safe immutable starting state without designing future rating engine now. Storage direct upload with RLS avoids upload proxy/binary Worker code. No new dependencies; no community-scoped state. Preserve future rating-worker migration path via engine/version constants and deny-by-default grants.
- Components to be modified/created: `supabase/migrations/20260928000000_player_profiles_and_ratings.sql` (next unique timestamp; check before use), `src/features/player/rating-config.ts`, `src/features/player/player.validators.ts`, `src/features/player/player.functions.ts`, `src/features/player/PlayerOnboarding.tsx`, `src/features/player/PlayerProfile.tsx`, `src/features/player/AvatarUpload.tsx`, `src/features/auth/auth.functions.ts`, `src/features/auth/return-path.ts`, `src/routes/{login.tsx,auth.callback.ts,_protected.tsx,_protected.dashboard.tsx}`, new `src/routes/onboarding.tsx`, `src/lib/supabase/database.types.ts` (generated), `src/locales/{en,pt-BR,es}/translation.json`, token sources and compiled output **only after approval**, tests below. Delete `src/features/notes/notes.functions.ts`, `e2e/notes.spec.ts`; keep historical notes migration for replay safety. `src/routeTree.gen.ts` regenerates through TanStack build; never hand-edit.

2. **Persist app-wide data and avatar bucket.** Add append-only migration `supabase/migrations/20260928000000_player_profiles_and_ratings.sql` with following complete SQL (adjust timestamp only to avoid collision). Explicit grants override Supabase default grants. Owners can SELECT both rows, edit **only** `player_profiles.display_name`, `preferred_side`, `dominant_hand`, `bio`, `avatar_url`; rating insert/update always rejected to regular clients. Function is the only onboarding write path. `avatar_url` stores a **private bucket object key**, not public URL. `updated_at` is database-owned. SQL:

   ```sql
   create table public.player_profiles (
     user_id uuid primary key references auth.users(id) on delete cascade,
     display_name text not null check (char_length(btrim(display_name)) between 1 and 80 and display_name = btrim(display_name)),
     avatar_url text check (avatar_url is null or (char_length(avatar_url) <= 256 and avatar_url like user_id::text || '/%')),
     preferred_side text not null check (preferred_side in ('LEFT', 'RIGHT', 'EITHER')),
     dominant_hand text check (dominant_hand in ('LEFT', 'RIGHT')),
     bio text check (char_length(bio) <= 280),
     created_at timestamptz not null default now(),
     updated_at timestamptz not null default now()
   );

   create table public.global_player_ratings (
     user_id uuid primary key references public.player_profiles(user_id) on delete cascade,
     initial_display_level numeric(3,1) not null check (initial_display_level between 0.0 and 7.0),
     mu numeric(4,2) not null check (mu between 0.00 and 7.00),
     sigma numeric(3,2) not null check (sigma > 0.00 and sigma <= 7.00),
     display_level numeric(4,2) not null check (display_level between 0.00 and 7.00),
     reliability_percent smallint not null check (reliability_percent between 0 and 100),
     confirmed_competitive_game_groups integer not null check (confirmed_competitive_game_groups >= 0),
     highest_display_level numeric(4,2) not null check (highest_display_level between 0.00 and 7.00),
     last_rating_at timestamptz,
     rating_engine text not null check (char_length(rating_engine) between 1 and 64),
     rating_engine_version text not null check (char_length(rating_engine_version) between 1 and 32),
     updated_at timestamptz not null default now(),
     constraint highest_not_below_current check (highest_display_level >= display_level)
   );

   create function public.touch_player_updated_at() returns trigger
   language plpgsql set search_path = '' as $$
   begin
     new.updated_at := now();
     return new;
   end;
   $$;
   create trigger player_profiles_touch_updated_at before update on public.player_profiles
     for each row execute function public.touch_player_updated_at();
   create trigger global_player_ratings_touch_updated_at before update on public.global_player_ratings
     for each row execute function public.touch_player_updated_at();

   alter table public.player_profiles enable row level security;
   alter table public.global_player_ratings enable row level security;
   revoke all on public.player_profiles, public.global_player_ratings from public, anon, authenticated;
   grant select on public.player_profiles, public.global_player_ratings to authenticated;
   grant update (display_name, avatar_url, preferred_side, dominant_hand, bio)
     on public.player_profiles to authenticated;
   create policy "player profile owner select" on public.player_profiles
     for select to authenticated using ((select auth.uid()) = user_id);
   create policy "player profile owner update" on public.player_profiles
     for update to authenticated using ((select auth.uid()) = user_id)
     with check ((select auth.uid()) = user_id);
   create policy "global rating owner select" on public.global_player_ratings
     for select to authenticated using ((select auth.uid()) = user_id);
   -- No INSERT policies on either table, no UPDATE policy on rating: onboarding uses the trusted RPC.

   create function public.onboard_player(p_display_name text, p_preferred_side text, p_initial_level numeric)
   returns void language plpgsql security definer set search_path = '' as $$
   declare v_user_id uuid := (select auth.uid());
   begin
     if v_user_id is null then
       raise exception 'Authentication required' using errcode = '28000';
     end if;
     if p_display_name is null or char_length(pg_catalog.btrim(p_display_name)) not between 1 and 80
       or p_preferred_side is null or p_preferred_side not in ('LEFT','RIGHT','EITHER')
       or p_initial_level is null or p_initial_level < 0 or p_initial_level > 7
       or p_initial_level * 10 <> pg_catalog.trunc(p_initial_level * 10) then
       raise exception 'Invalid onboarding input' using errcode = '22023';
     end if;
     perform pg_catalog.pg_advisory_xact_lock(pg_catalog.hashtextextended(v_user_id::text, 0));
     if exists (select 1 from public.player_profiles where user_id = v_user_id)
       or exists (select 1 from public.global_player_ratings where user_id = v_user_id) then
       if exists (select 1 from public.player_profiles where user_id = v_user_id)
         and exists (select 1 from public.global_player_ratings where user_id = v_user_id) then
         return; -- duplicate submit/callback never resets the initial rating/profile
       end if;
       raise exception 'Incomplete player state' using errcode = '23514';
     end if;
     insert into public.player_profiles (user_id, display_name, preferred_side)
       values (v_user_id, pg_catalog.btrim(p_display_name), p_preferred_side);
     insert into public.global_player_ratings
       (user_id, initial_display_level, mu, sigma, display_level,
        reliability_percent, confirmed_competitive_game_groups, highest_display_level,
        rating_engine, rating_engine_version)
       values (v_user_id, p_initial_level, p_initial_level, 1.00, p_initial_level,
               10, 0, p_initial_level, 'app-wide-level', '1.0.0');
   end;
   $$;
   revoke all on function public.onboard_player(text, text, numeric) from public, anon;
   grant execute on function public.onboard_player(text, text, numeric) to authenticated;

   insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
     values ('player-avatars', 'player-avatars', false, 2097152,
             array['image/jpeg','image/png','image/webp']);
   create policy "avatar owner select" on storage.objects for select to authenticated
     using (bucket_id = 'player-avatars' and (storage.foldername(name))[1] = (select auth.uid())::text
       and array_length(storage.foldername(name), 1) = 1);
   create policy "avatar owner insert" on storage.objects for insert to authenticated
     with check (bucket_id = 'player-avatars' and (storage.foldername(name))[1] = (select auth.uid())::text
       and array_length(storage.foldername(name), 1) = 1);
   create policy "avatar owner delete" on storage.objects for delete to authenticated
     using (bucket_id = 'player-avatars' and (storage.foldername(name))[1] = (select auth.uid())::text
       and array_length(storage.foldername(name), 1) = 1);
   -- No avatar UPDATE policy; use unique keys, upsert:false, and explicit owner delete.
   ```
