## Chosen Approach

- Proposed solution: Repair causal boundaries using existing Playwright fixtures, real built SW, actual server functions/SQL, and existing visual helpers. Investigate then implement each class sequentially; annotate proven mechanisms in its spec and correct historical shorthand in shard comments. Keep evidence in `docs/plan/PAF-175-findings.md` managed by parent and ignored/approved temporary reporter artifacts, without introducing a new performance framework.
- Justification for simplicity:
  - Option A, more serialization/retries/timeouts or weaker assertions: cheapest but fails AC1/AC3 and misses the preview artifact bug. Reject.
  - Option B, narrow lifecycle management, production-only build guard, gated real cutoff request, and render-readiness/data isolation: selected. Keeps current contracts and infrastructure; each change has a direct negative/regression oracle.
  - Option C, global shared browser profiles, replacement SW implementation, broad bundler upgrades, clock virtualization across app/database, or general visual stabilization framework: adds isolation/version/architecture risk. Reject unless narrow evidence makes a bounded part indispensable; return material scope decisions to parent.
  - Important findings refine issue suggestions: PWA already waits for `serviceWorker.ready` and polls controller. Preferences mocks already block native workers. `DevStyleXInject.tsx` is a concrete producer of `/virtual:stylex.css`, not merely an assumed leaked chunk. Current cutoff spec inserts third invitation **before** click; realtime `refresh()` can advance `asOf`. Geometry helper samples boxes across separate browser evaluations, allowing torn layout snapshots. None of these observations alone proves the full runtime cause.
