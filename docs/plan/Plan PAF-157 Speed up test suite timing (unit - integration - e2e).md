## Chosen Approach

- Proposed solution: Bounded concurrency with explicit isolation boundaries; one @visual classification; measured deterministic functional-spec groups; immutable same-run build artifact; versioned Docker-image cache; gate-owned preparation with standalone-safe entry points.
- Justification for simplicity:
  1. Chosen: shared DB with audited parallel-safe files and a non-overlapping serial phase. Reuses existing experiment and fixtures, improves local and CI together, retains an immediate serial rollback. Two workers reduce lock/connection pressure.
  2. Rejected as default: two integration CI jobs with independent stacks. Strong isolation but repeated startup overhead, extra CI cost, no equivalent local gain. Approved technical fallback if repeated proof exposes irreducible shared-state interference; still audit/partition and measure local improvement.
  3. Rejected: schema-per-worker/DB-per-file, dynamic CI scheduling service, broad fixture-framework rewrite, fewer assertions/screenshots or nightly visual exclusion. Excess complexity or violates scope. Checked-in runtime weights + three deterministic groups suffice; direct tag filtering avoids duplicate browser projects/baseline churn.
- Components to be modified/created:
  - Unit 1 expected: `vitest.integration.config.ts`; small `scripts/run-integration.mjs` plus declaration if imported by TS tests; `test/integration-execution.test.ts`; audited fixture/helper files only where needed; `test/statistics.performance.integration.test.ts`; small promise-pool helper and unit test under `test/helpers/`; `playwright.config.ts`; mixed/dedicated visual spec tag metadata; `e2e/player-ratings.spec.ts` and fixture helper if diagnosis requires; `scripts/e2e-shards.mjs` with compact runtime-weight/group data; `test/e2e-shards.test.ts`; small prebuilt-artifact verifier/runner and tests; `.github/workflows/ci.yml`; minimal local Docker-image-cache action under `.github/actions/` to avoid five copies; `package.json`; narrow CI contract tests. Reuse existing harnesses; prefer colocated tests over extra abstractions.
  - Unit 2 expected: `scripts/complete-check.mjs`, `test/complete-check.test.ts`, `package.json`, shared E2E runner contract/tests from unit 1, and only necessary updates to AGENTS.md toolchain notes describing reset ownership and fast lane. No hook changes.
  - Budget: aim 1000–1500 changed lines / ≤40 files; tagging eleven standalone visual files + three mixed files consumes fourteen files. Keep helper count small, reuse current fixtures. If isolation genuinely needs more, report evidence; soft budget never licenses leaving related defects unresolved.

### Contracts and risk controls

- Integration: `INTEGRATION_SERIAL=1` means all selected integration files run serially, once; default safe files maxWorkers=2, unsafe files one worker in a separate non-overlapping phase. Keep retry/repeats=0, current timeouts, scheduler pause/restore. New/unclassified files default serial until reviewed. Explicit complete, disjoint partition tested against filesystem inventory. Runner forwards file filters, reporters and JSON outputs without running files twice; merge/retain reports per phase without overwrite. Aggregate failing phase status after both phases. A project called serial is NOT isolation if another project runs at the same time.
- Visual: tag `@visual` via Playwright metadata on describe/tests; standalone visual files get one enclosing describe tag without changing test title hierarchy where possible (describe.configure tag support must be checked; otherwise existing top-level describe metadata). Mixed tests get tags individually; whole dependency-connected serial group tagged if necessary. Do not move assertions or rename files/projects/snapshots. Diagnostic screenshots alone do not make a functional test visual. CI functional entries use `--grep-invert @visual`, dedicated visual entry `--grep @visual`; local fast lane uses identical inverse filter. Full local gate has no filter.
- Integration DB-sharing risk HIGH: global revisions, table-wide DDL, cleanup, jobs, shared ports and projection locks. Unsafe phase cannot overlap any other integration files or DB-touching gate. Rollback `INTEGRATION_SERIAL=1` restores existing semantics immediately; emergency rollback does not satisfy performance AC until safe solution/fallback verified. Never mask flakes with retries/timeouts/assertion edits.
- Build-sharing risk HIGH: Vite public config embedded at build, generated unit imports outside dist, Cloudflare metadata and permissions/hidden files. Artifact keyed by current Actions run ID/attempt and commit, manifest includes source SHA, public config fingerprint, exact required outputs. Download only same-run artifact; fail closed on mismatch/missing output. CI marker does not authorize arbitrary dist reuse. Runtime service-role key stays job-local and masked. Local gate passes prebuilt mode only after its own successful build.
- Populated-upgrade false-negative risk: filter all `supabase/**` (migrations, seed, config, templates), `scripts/test-populated-migration-up.*`, `test/fixtures/**`, migration harness test, package/lock/tool-version files and workflow/cache/filter implementation. Compare full PR diff against base; push against before SHA; handle renames/deletions and missing history. Unknown/unavailable diff means RUN, never skip. Changes gate only populated harness, not integration/types/latest reset. No top-level workflow path filter that skips required checks.
- Docker cache: cache image archives only, never volumes, DB data, credentials or .env. Key OS+architecture+Supabase version/lock+config+cache format. Enumerate actual images needed by pinned CLI; cold/partial/corrupt cache falls back to normal pulls. One integration job saves immutable cache; all consumers restore/load before start. Concurrent first cold run may miss everywhere; measure warm separately. Avoid broad Docker image prune/save of unrelated runner images.
- Runtime drift: checked-in weights sourced from successful, non-retry per-spec runs, longest-processing-time deterministic assignment to three functional bins; serial file indivisible. New specs get explicit conservative default and enter exactly one bin. Mixed visual filters require functional-only weights. Keep all tests discoverable; regenerate groups from evidence within same PR if max shard remains a tail. No claim that file byte size is Playwright scheduling behavior without verifying actual reporter inventory.
- Local reset removal risk HIGH: integration residue may poison E2E global listings/claims. Existing `e2e/global-setup.ts` fixture-scoped prune is designed for post-integration execution, but prove it covers current derived evidence/FKs. Required scoped cleanup fixes remain here; never broad truncate/delete real developer rows. A failed shared reset blocks dependent phases, never allows stale DB success.
