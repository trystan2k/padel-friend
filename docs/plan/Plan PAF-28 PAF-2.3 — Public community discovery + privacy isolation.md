## Chosen Approach

- Proposed solution: Add `listPublicCommunities` and `getPublicCommunity` as `createServerFn({ method: 'GET' })` in `community.functions.ts`, each with strict input validation in `community.validators.ts` and `requireAuthenticatedClient()` in its handler. Reuse **one explicit nine-column projection** (constant if convenient) and `client.from('communities')`, with `visibility = 'public'` in **both** queries. List takes `{ search?: string, offset?: number, limit?: number }` (default offset 0, limit 20; integer offset 0–10000, integer limit 1–50). Normalize surrounding whitespace; empty/whitespace-only search means no name predicate; otherwise max 80 Unicode code points, reject NUL/lone surrogate, escape literal `%`, `_`, `\` then `.ilike('name', '%' + escaped + '%')` for case-insensitive substring matching. Stored names are searched as-is, including non-English text; no translation/transliteration promise. Order `created_at DESC, id DESC` (stable ties); `.range(offset, offset + limit)` fetches one sentinel row, return `{ communities: rows.slice(0, limit), next_offset: rows.length > limit ? offset + limit : null }`; no total count, no joins, no `select('*')`, no service-role or shared caching. Offset chosen over cursor: straightforward bounded discovery with existing `(visibility, created_at DESC)` index; concurrent inserts can shift pages, acceptable for this issue, whereas cursor/compound-key tokens add unnecessary contract complexity. Detail validates `{ community_id: UUID }`, selects nine columns with `.eq('id', community_id).eq('visibility', 'public').maybeSingle()` and returns row or `null` for **both private and nonexistent IDs**, even to a member/Admin; never query private first. Database errors propagate (not interpreted as absence); invalid input yields `INVALID_COMMUNITY_INPUT`, missing/expired claims yield `UNAUTHENTICATED`.
- Justification for simplicity: (A) **Chosen:** direct, RLS-governed, explicitly projected SELECT with public filter; no privileged bypass and no post-fetch stripping. (B) `select('*')` then sanitize rejected: forbidden fields cross server boundary and may leak on future return/log changes. (C) SECURITY DEFINER discovery RPC/view or new search index/cursor rejected: extra privilege/schema/type churn with no demonstrated need; RLS and current index already cover this scope. Brainstormed attack surfaces: direct private-ID/filter/list probes, name wildcard injection, anonymous session, active vs pending/inactive membership, members/Admin seeing private rows through RLS but **not** public-only endpoints, missing/private indistinguishability, null fields, empty search, bounds, same-timestamp pagination, and translated names. RLS applies at DB row boundary; the server's explicit projection + visibility filter applies independently at API/payload boundary.
- Components to be modified/created (**exact five-file implementation delta including plan**):
  - **CHANGED** `src/features/community/community.functions.ts` — add shared public-column projection and two GET handlers; typed authenticated client, `visibility = 'public'`, `ilike`/ordering/bounded range, `maybeSingle`, no-cache inherited from auth helper; leave create/settings behavior untouched.
  - **CHANGED** `src/features/community/community.validators.ts` — export list/detail input types and validators with exact allowlists, normalized literal search, bounded pagination/UUID checks; reuse existing `INVALID_COMMUNITY_INPUT`, SQL-safe text helper or same validation semantics.
  - **NEW** `test/community.discovery.functions.test.ts` — focused mocked builder/client unit tests running real validators and auth helper; assert precise query projection/filter/order/range, payload shape, error/no-oracle behavior.
  - **CHANGED** `test/community.integration.test.ts` — add focused real-JWT list/detail role matrix and direct-client private-row leakage probes within existing loopback/CI-guarded suite; reuse its already-created Admin/member/outsider/public actors and private/public communities.
  - **NEW** `docs/plan/Plan PAF-28 PAF-2.3 — Public community discovery + privacy isolation.md` — this plan, matches deferral and direct-public-column limitation documented. **Untouched:** `supabase/migrations/*`, `src/lib/supabase/database.types.ts`, routes, locale files, package/CI config.
