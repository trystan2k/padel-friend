## Chosen Approach

- Proposed solution: One canonical PostgreSQL fact-to-counter query, rebuildable per-League materialized earned counters, idempotent confirmation projection before existing global rating projection, SQL sporting rank/award flags, transactional immutable final snapshot versions tied to existing close lifecycle and late-first-confirmation evidence, existing SSR League UI upgraded to consume those contracts.
- Justification for simplicity: Keep calculations next to immutable confirmed facts and membership intervals. Rebuild one affected League on a new eligible confirmation initially: simpler and safer than additive delta bookkeeping with subtract/replay rules; no cross-League/global replay. Unique projection receipts make retries harmless. SQL defines ranking once for live and final readers. Existing cron, lifecycle locks, routes, forms, authorization and translations remain owners.
- Components to be modified/created: `supabase/migrations` (new forward migrations), `src/lib/supabase/database.types.ts`, League DTO/decoder/validator/server seams and page components, three locale JSON files, shared test fixture/cleanup helpers, focused League tests and E2E reference artifacts. Likely new modules named `league-standings-contracts.ts` / `league-standings-decoders.ts` / `league-standings.functions.ts` if existing modules would become unwieldy; use feature-local ownership, not generic repositories/services.

### Options compared

1. Calculate everything on each read, snapshot at close: smallest modification to T11 but fails explicit materialized counters requirement and repeats fact scans. Retain canonical raw query as rebuild oracle, not production standings path.
2. **Selected:** per-League synchronous rebuild plus small materialized table/receipt set and immutable snapshot records. Fits existing serialization and modest V1 workload; exact all-or-nothing confirmation transaction; straightforward consistency proof.
3. Per-player delta ledger + async event bus/queue/realtime projection: additional lag, idempotency/reversal machinery and operational dependencies without scope need. Reject. No generic event-sourcing platform or coupling to rating ledger.

Performance checkpoint: index bound-event/confirmation joins; assess representative fixture cardinality/query plan and lock duration. If measured per-League rebuild is too costly, optimize changed-player recomputation behind identical canonical contracts within this delivery; do not silently adopt asynchronous stale standings or schedule correctness follow-ups.

### Shared DB and API contracts

**Canonical source.** Extract internal `league_eligible_confirmed_groups(p_league_id, optional_confirmation_cutoff)` and counter aggregation from current T11 SQL. Join `match_events.league_id` → `match_event_result_confirmations` → exact `match_event_result_proposal_versions`; require Competitive, ratable confirmation, classification explicitly in `team_a/team_b/draw` and existing Ranked helper success. Completed sets only. One contribution per immutable confirmation/group/player. No ratings table/function inputs. Keep `get_league_counters` payload compatible and read-only, delegating shared raw aggregation; it remains useful as regression/rebuild oracle rather than a second source of sporting logic.

**New tables (names proposed, contracts mandatory).**

- `league_player_counters`: PK `(league_id,user_id)`; community-scoped FK, permanent player UUID, integer matches/wins/losses/draws/sets_won/sets_lost, differential generated/derived rather than independently mutable. Nonnegative counters; `matches=wins+losses+draws`. Store earned rows; overlay open current-active members at zero in reader, so membership join needs no write trigger and leaving never deletes earned rows.
- `league_projection_confirmations`: unique `(league_id,confirmation_id)`, source proposal/version/event/group references and projected timestamp; retain immutable applied identity. Four players applied atomically, no partial receipts. Source identity permits proving no duplicates and safe repair. Never read rating event tables as projection inputs.
- U3 adds `league_standings_snapshots`: PK `(league_id,standings_version)`; community scope; generated timestamp, effective period bounds, frozen threshold, cause (`closed` / `late_first_confirmation` / explicit migration reconstruction), nullable triggering confirmation FK, source-count/evidence, immutable rows JSONB carrying UUID, display label/provisional label snapshot, counters, shared position and award eligibility. Validate JSON shape and validate all rows through typed decoder. Unique triggering-confirmation per League where present. Latest version obtained by indexed descending PK; no mutable pointer needed. Closed `leagues.version` remains metadata version, distinct from `standings_version`.
- Snapshot row arrays are natural for whole-table versions and avoid a second snapshot-child table. Store ordered rows from same SQL rank function; never re-sort/recompute an old snapshot at read time. Preserve sporting facts despite later membership/profile edits. Permanent UUID remains identity after provisional claim. Current profile badges may be supplementary, not replacements for frozen record.
- Existing `league_events`: extend action/system-reason checks narrowly for final snapshot publication/late first confirmation/reconstruction. Append evidence with old/new standings versions, triggering confirmation/proposal/version, actual source/actor or system reason, play/confirmation times and effective cutoff. Preserve immutable audit trigger and actor-or-system invariant. Never pretend late first confirmation is T15 correction.

All new public-schema tables: RLS enabled, runtime writes revoked; no raw audit/receipt table API access. Follow existing internal SECURITY DEFINER + empty search_path + revoked PUBLIC/anon/authenticated/service_role EXECUTE conventions. Expose only narrow authenticated, nonanonymous, nonprovisional, active-community-member read RPCs with unknown/unreadable IDs indistinguishable; owner/Admin check for close both before and under lock. Add restrictive provisional policies to any table granted direct SELECT; prefer RPC-only new tables. Audit reader exposes only safe League publication metadata, not arbitrary match result evidence, email or cross-community data.

**Projection/rebuild transaction.** Internal projector receives source identity, re-reads facts, resolves bound League, and runs only before rating projector. Community already locked by shared result finalizer. Lock League then materialization/receipt rows consistently. On first eligible receipt: rebuild affected League's earned counters from canonical source, insert receipt, and (after U3) append new closed snapshot if needed. Retry receipt means no counters, snapshot, audit or version duplication. Existing confirmed replay may repair missing projection receipt; it must not create fake “new confirmation” if source already included in latest snapshot. Use source-evidence comparison, not wall clock, to distinguish repair from first inclusion.

Internal rebuild entry takes community→League locks itself, re-aggregates same facts/intervals and repairs counters/receipt coverage, comparing before/after. Rebuild with identical input leaves sporting values and closed snapshot history unchanged. If real eligible evidence missing from a closed final is discovered, append truthful repair/reconstruction evidence and version, never overwrite history. No browser “rebuild” capability. Include backfill for already-confirmed groups and closed Leagues in deployment migrations, with source timestamps preserved.

**Close + snapshot.** Reuse `league_process_community_locked` for Fixed/expired-Upcoming transitions and `close_league` for Manual; invoke one internal publication function after status/effective cutoff becomes closed inside same transaction. Rebuild canonical counters under cutoff before v1; empty/expired-unused League gets valid empty snapshot. Existing closure audit stays single; snapshot audit references version. Automatic due processor retains singleton/fairness/bounded attempts/skip-locked behavior. Fixed `closed_at=end_at` even after delayed scheduler; Manual `closed_at` sampled **after** community/League locks, not request-start timestamp. No source-event locks acquired by close/rebuild: read committed immutable facts under community serialization.

Idempotent Manual-close contract: same authorized request/version already produced Manual close → return existing closed DTO/snapshot identity with no extra audit/version. Can preserve two-argument RPC and recognize exactly `closed_reason=manual AND current metadata version=expected_version+1` under rechecked owner/Admin authorization; stale unrelated edits still conflict. Repeat with current closed version may also return existing outcome. Explicitly test stale/version semantics; never let idempotency bypass permissions or allow Fixed early close. Avoid broader request-ledger machinery unless existing signature cannot safely meet these tests.

**Races and locks.** Community row is shared serialization boundary for confirmation, membership, activation and close. Preserve existing event advisory/row→registration/proposal locks and source prelocks. New League projection/publication completes before `project_confirmed_rating_group`; rating remains last. No rating callback into League projection. Confirmation winning race enters v1; close winning race produces v1 then late in-period confirmation produces v2. Both final results equivalent; every visible version internally consistent. Preserve one-active index and lifecycle reconciliation before allocating successor. Never move source locks to after global lock. Backfill/rebuild acquire locks in same order, one community/League at a time.

**Read contract.** New `get_league_standings(league_id, optional standings_version)` returns League-scoped ordered entries with counter fields, `position`, `award_eligible`, `matches_remaining`, source status/live-or-final, threshold, cutoff, snapshot version/generated time and safe revision reason. Closed default latest immutable version; explicit version reads exact old version; live version request invalid. New `list_league_standings_versions` provides bounded keyset history and safe publication audit metadata. Current League list already provides keyset pagination; preserve it. Sporting rank uses only Wins desc, Losses asc, Set Diff desc, Sets Won desc. UUID tie presentation never enters rank window; Draws/Matches/skill do not become extra tiebreaks. Build entire payload in one SQL statement/snapshot so metadata and counters correspond.
