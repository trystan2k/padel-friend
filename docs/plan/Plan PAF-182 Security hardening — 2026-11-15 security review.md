## Chosen Approach

- Proposed solution: **Incremental, boundary-focused hardening.** Thirteen ordered vertical slices, each containing migration/contracts/callers/fixtures/tests as necessary. Reuse existing authenticated clients, RPC governance, diagnostics, StyleX/Base UI, i18n, integration helpers and final quality gate.
- Justification for simplicity:
  1. **Selected:** narrow forward migrations plus small shared security helpers. Database owns authorization/rate limits; Worker owns response headers; server-function boundary owns public errors. Each security control exists where bypassing React cannot evade it.
  2. **Rejected:** server-only authorization wrappers retaining broad DB grants. Direct PostgREST bypass remains; captcha/client validation alone likewise cannot enforce database limits.
  3. **Rejected:** generic policy engine, new rate-limit infrastructure, wholesale auth/response middleware rewrite, full 374-function audit. More complexity, deployment dependencies and scope than acceptance criteria require.
- Components to be modified/created:
  - Existing feature modules and narrow new helpers under existing owners; new migrations under `supabase/migrations/`; generated `src/lib/supabase/database.types.ts`.
  - Shared client-error vocabulary/sanitizer under `src/lib/`, request security-header helper, shared password policy, avatar image validator, origin validator, pure push-endpoint validator.
  - `test/` unit/integration cases and supporting builders; affected `e2e/` specs. New test filenames below are proposed names; reuse equivalent existing cases rather than duplicate.
  - `.github/workflows/{ci,preview,release}.yml`, `.github/actions/supabase-start/action.yml`, `.github/dependabot.yml`; package manifest/lockfile; `INITIAL_SETUP.md`; static guard script and gate contract tests.

### Shared implementation contracts

- **RPC security:** fully qualified SQL; `SECURITY DEFINER SET search_path = ''`; actor derives from `auth.uid()`; anonymous/provisional/revoked guards consistent with existing policy; exact authorization/community scoping; explicit argument validation; revoke EXECUTE from `PUBLIC`, `anon`, `authenticated` before narrow grant. Service-only helpers never authenticated-executable. Preserve return shapes, transactions and audit semantics.
- **Error vocabulary:** PAF-183 creates one typed allowlist module, proposed `src/lib/client-error-codes.ts`, containing new community RPC codes and existing consumed codes needed by that unit. Use existing codes where their semantics match (`NOT_COMMUNITY_ADMIN`, `COMMUNITY_VENUE_NOT_FOUND`, `COMMUNITY_NOT_ELIGIBLE`, `ALREADY_MEMBER_OR_PENDING`, `INVITATION_ALREADY_OPEN`, `INVITEE_NOT_FOUND`, `INVITATION_NOT_FOUND`, generic operation failure). PAF-187 completes this same registry, never a competing list. SQLSTATE is input to mapping, never output; application code must match exact allowlist entry, not merely uppercase regex or message substring. PAF-189 appends its distinct codes there.
- **No data leaks:** unknown input becomes generic allowlisted Error; never attach original `cause`, `details`, `hint`, constraint/table names, SQLSTATE, tokens or subscription values to public payload. `emitDiagnostic` plus `safeErrorCode` record safe structured telemetry; no raw PII-bearing error dump.
- **Testing:** production logic never gets test-only rate-limit exemption, injectable arbitrary clock via public RPC, captcha bypass accepted by prod, or arbitrary endpoint/origin allowance. Trusted SQL builders may establish test state directly.
- **Scope staging:** before each commit capture exact changed file list; shared files belong only to current unit's delta. Avoid whole-branch staging and preparing later-unit source early. Plan/bundle/log artifacts attach only where orchestrator directs, never as extra implementation unit.
- **Rollout:** local tests first. Forward correction for failed migrations; no broad grant restoration as normal rollback. Block release instead of weakening controls. Except approved PAF-181 repair, production deployment awaits established release procedure and explicit push/PR approval.
