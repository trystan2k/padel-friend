## Chosen Approach

- Proposed solution: **A — one route and URL-addressable create view.** Add `src/routes/onboarding_.community.tsx` for `/onboarding/community`, with strict `validateSearch` for optional `q` (bounded to server's 80-code-point limit) and `view=create`; `beforeLoad` checks auth first, then profile completion; discover `loader` obtains first 20 public rows with `listPublicCommunities`, while create view skips that fetch. `loaderDeps` includes validated query/view, so SSR and hydrated render use the same result. Feature view uses responsive cards and a native, accessible search field; debounced URL `replace` for live search, explicit pending/empty/error/retry states and bounded `next_offset` pagination if results exceed 20. In create view use name, native radio group for Public/Private, real optional description and city/area controls; submit validated data to existing `createCommunity` (`public` → `instant`; `private` → `admin_approval`, a documented minimal mapping because JO4DC has **no** join-policy selector). On success, show confirmation and offer `/dashboard` completion; Back returns to discovery preserving query. In discovery JOIN and REQUEST TO JOIN are labels selected from `join_policy`; **both** call `joinCommunity` once and trust returned `active|pending` to show joined/request-sent status. Skip always routes to `/dashboard`, even if list fails, without any membership mutation. Extend `listPublicCommunities` narrowly to match `name OR city_label` server-side, preserving authenticated/public-only filter and existing literal, case-insensitive substring semantics; verify safe PostgREST `.or` filter escaping with real malicious/special-character inputs before release.
- Justification for simplicity: **B — separate create route** adds duplicated beforeLoad/loading/copy/state plumbing and another route-tree/file slot for one wizard step; reject. **C — modal** complicates small-screen form, focus/history, SSR and visual parity; reject. **D — filter city client-side on 20 loaded cards** gives false negatives across pages; reject. Existing RPCs own membership and Admin bootstrap; no new write endpoint/role handling. Brainstormed edge cases: no communities, no matches, delayed/out-of-order search, failed list while skip remains usable, duplicate join/pending request, session expiry after loader, invalid name/optional inputs, private creation not discoverable, reload/Back on create, translated text wrap, keyboard radio/search, browser font rasterization.
