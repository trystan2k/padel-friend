## Chosen Approach

- Proposed solution: Single transactional in-app store feeds a private Push outbox on new notification insert. Existing Workers cron claims bounded jobs, fans out to active subscriptions, sends standards-based VAPID Web Push, retries transient failures and retires expired endpoints. Browser device state and saved account preferences remain distinct. All Push taps open recipient-private notification detail, which resolves current authorized domain destination. SW caches only explicit public build assets and a nonauthenticated offline document; never private navigation or API responses.
- Justification for simplicity: Compared (1) direct sends in every mutation: no durable retry/crash guarantee, misses SQL cron producers; rejected. (2) Supabase Edge Function plus webhook/event bus: another runtime/secret/scheduler/deployment surface with no existing local pattern; rejected. (3) transactional notification insert hook plus existing Workers cron: chosen; one universal producer seam, current DB claim/settle conventions, and failure isolation from domain writes. No broker, Push provider SDK, browser background sync or per-producer network calls.
- Components to be modified/created: `public/manifest.webmanifest` and icons/offline document; `scripts/generate-sw.mjs`; authored SW entry plus build integration; `PwaRegistration.tsx`; focused `src/features/pwa/*` and `src/features/notifications/push-*` browser/server modules; existing notification preference/detail/model/functions/styles modules and protected route adapters only where necessary; new additive migrations, generated `database.types.ts`; `src/server.ts`; config/setup/security documentation; locale files; focused Vitest/integration/Playwright contracts and fixtures. Exact file splits may refine responsibility, not acceptance scope.

### Contracts and decisions

**PWA/SW:** Keep `/sw.js` registration URL and scope stable. Switch Workbox build from generateSW to injectManifest with authored source (for example `src/features/pwa/service-worker.ts`, bundled to a temporary build output through existing build tooling). Add explicit matching-version Workbox precaching/routing modules as dependencies only if imported; follow `.npmrc` tilde policy. Precache same-origin content-hashed build JS/CSS/fonts plus vetted public manifest/icons/offline asset. Remove arbitrary HTML glob; offline document is sole explicit HTML exception. No cross-origin runtime image/font cache. Requests to navigation, server functions, APIs, Supabase endpoints (especially `/auth/v1`), non-GET, Authorization-bearing requests, or anything outside explicit public asset allowlist never enter CacheStorage. Private SSR request always goes network; offline navigation may return public offline document, never cached route HTML. Offline document contains no account data, reads no session storage/cookies and offers reconnect/retry, not fake authenticated shell. Generate its three-language copy from locale resources with deterministic locale selection; use token-derived styles/metadata, no component prose literals. No auth callback fallback masking: failed auth network must remain failed, not synthetic success.

Update remains user-controlled: waiting worker announces translated update action; send SKIP_WAITING only on confirmation. Prevent reload while a mutation is pending or unsaved result form exists; offer deferred reload without losing form. One controllerchange reload, no loops or automatic permission request. Remove known old generic runtime caches on activate to clear earlier overly broad entries without touching unrelated applications. SW fetches neither private data nor cached account state on Push.

**Subscription persistence:** Add `push_subscriptions`: UUID, `user_id` FK cascade, unique endpoint (size bounded), `p256dh`, `auth`, VAPID key ID, locale enum, created/updated/last-seen timestamps, optional expires_at and retired_at/reason. Endpoint/key material sensitive: owner-only necessary DTOs, no endpoint logs, no analytics/raw UA requirement. RLS enabled; no anon privileges/direct browser writes. Restricted owner RPCs derive auth.uid, reject anonymous identities, validate lengths, HTTPS endpoint and decoded key lengths, and register/upsert, list current device metadata, retire owned subscription. Never accept arbitrary user_id. Prevent endpoint theft: different active owner cannot silently overwrite registry ownership; explicit logout/device cleanup retires old association before another account registers. Test account switch and failed cleanup; new account must not inherit old account sends.

Authenticated `push.functions.ts` wrappers use normal user client/getClaims, hand validators, allowlisted DTOs; public key config read exposes no private key. Browser stores no durable private account DTO. Use native PushManager subscription as device identity. Reconcile getSubscription on settings entry/login, permission change/focus and key change; preserve multiple other devices. Retire stale registry row before replacing endpoint; compensate failed registry save by unsubscribing newly created subscription or show explicit retry/disabled state. Global preference off suppresses all sends without forcing other devices to unsubscribe. Separate explicit “disable this device” retires registry then unsubscribes, with retry on partial failure. Logout best-effort client unsubscribe plus server retirement while authenticated; payload privacy protection still applies if network cleanup fails.

**Permission/install UX:** Feature-detect secure context, ServiceWorker, PushManager, Notification and standalone display. iOS/iPadOS browser context requires installed Home Screen app; explain install first. Detect iPadOS desktop UA where relevant; capability detection remains primary. Distinct loading/config unavailable, unsupported, install-required, default permission, denied, granted-not-subscribed, enabled, expired/key-change, save/subscribe failed and offline states. Never call requestPermission on load or merely saving preferences. Dedicated enable button invokes permission synchronously within user gesture (registration ready beforehand); await subscribe and owner persistence before reporting enabled. Existing saved true preference is intent, not proof this device is enabled. Install button uses beforeinstallprompt only if available; Safari guidance is manual; absence of Chromium event alone does not mean unsupported. Already-installed via display-mode/standalone/appinstalled, with listener cleanup and SSR-neutral initial state.

**Durable pipeline:** Add private `notification_push_jobs` unique notification ID and `notification_push_deliveries` unique `(notification_id,subscription_id)`; jobs/deliveries reference persisted notification, with no capability to delete authoritative alerts. Notification AFTER INSERT trigger inserts one pending job in same transaction; trigger does no network/config/preference work. Domain retry cannot create another job because notification identity already dedupes. No historic blast/backfill by default: jobs begin at migration activation. Missing producers write normal `persist_notification`, automatically gaining both channels.

Service-only claim RPC uses SKIP LOCKED, attempt budget, next_attempt_at, lease expiry and random claim token; completion/retirement RPC compares claim token so stale worker cannot settle newer claim. Materialize eligible current subscriptions once per notification, require subscription created_at <= notification created_at (newly enrolled devices receive future events, no replay), and track per-device status so successful device never resent because another failed. Recheck global/category preferences and active subscription before each send/retry; missing prefs means Push off. Preference or retirement suppression is terminal skipped, never suppresses in-app. Lease recovery survives crash/overlapping cron. Due indexes and bounded batches follow player-add pattern; one job failure cannot starve others.

Choose `web-push` server-only adapter, tilde dependency (+ typings if needed), given existing nodejs_compat. **First delivery checkpoint must exercise actual encrypted HTTP send in Workers preview against local fake provider**; node-only unit success insufficient. Keep adapter small/injectable. If supported Node transport fails under Workers, replace adapter with Workers-compatible Web Crypto transport within PAF-162; no alternate deployment runtime or silently unencrypted payload. Verify RFC encrypted payload/VAPID audience/key/signature/headers using fixture vectors/provider verification. Outbound endpoints require allowlisted supported Push service hosts + HTTPS/default port, no credentials, IP/loopback/private hosts or arbitrary redirects; include current supported Chrome/Firefox/Apple service families in validator tests. Never allow client endpoint to become service-role SSRF capability. Fake provider injection only in isolated tests; no deployed “skip auth” or arbitrary-send endpoint.

HTTP 2xx → provider accepted, not OS delivered; 404/410 → retire only that subscription and mark delivery expired; 429 (respect bounded Retry-After), 5xx, timeout/network → bounded exponential backoff with jitter; invalid payload/400 → terminal failed; 401/403 → key/config fault, not endpoint expiry, no mass retirement. Attempts capped (e.g. 6) and TTL bounded (e.g. 24h from event), with durable exhausted state and sanitized logs. Scheduler uses existing five-minute cadence; document expected latency, no instantaneous delivery guarantee. WEB_PUSH_ENABLED=false prevents dispatch and exposes unavailable state, not silent success; misconfiguration leaves in-app intact, reports health and must not burn all attempts. Run both scheduled sweeps independently under waitUntil/allSettled, then surface failures so cron records failure; player-add unchanged.

At-least-once external delivery cannot guarantee exactly-once across send-success/DB-ack crash. Deduplicate DB channel identity, fence leases, and use stable browser `tag=notification:<uuid>` with renotify false to collapse retries; explicitly test lost ack. Do not claim cryptographic/exactly-once OS delivery. Payload is minimal versioned schema `{notificationId, category, title, body}` with generic translated category message, no community/player/venue/result names, scores or tokens; native display language derives from subscription locale. Require payload-size cap. Click handler derives same-origin `/notifications/<validated UUID>` itself; no arbitrary href. Malformed payload safe/no private fetch.

**Key rotation:** persist key ID per subscription; new enrollment uses current public key. Routine rotation retains old private key in server-only configured keyring until subscriptions migrate; emergency revoke retires affected key IDs, never alerts. Device reconciliation detects applicationServerKey mismatch, retires and re-enrolls only on explicit action if required by browser; explain re-enable state. Keys never generated on each build/deploy. Scan built browser JS/maps/SW for private key canary in addition to service-role guard.

**Deep links:** all categories initially land on `/notifications/$notificationId`, authenticate then load recipient-scoped resolver. Community invitation/membership/roles → existing detail and currently permitted community action; removed/denied membership → generic unavailable detail. Matches → `/matches/$matchEventId` through current SQL readability. Results → existing notificationResultHref, preserving historical proposal/version/group anchor; stale/current context never inferred from payload. Rankings level/reliability → current owner rating/history route or authorized owner detail; review decision → `/level-reviews/$requestId`. Leagues → existing community League detail after current membership/closed-snapshot authorization. Extend target RPC/decoder/detail actions for new kinds with same ownership-first contract; no private name on unavailable/foreign target. Notification open marks read only through existing explicit POST after authorization, never SW/GET. Focus existing same-origin window then navigate, or openWindow; signed-out/account-switched recipients hit auth/unavailable without leak. No new privileged deep-link shortcut.

### Elevated risks and mitigation

- **Privacy/SSRF/secret leak:** explicit public cache allowlist, generic lock-screen messages, ownership-first deep-link resolver, owner-only enrollment and service-only sender, endpoint host validation/no redirects, private VAPID/client canaries. Security regressions block release.
- **Missing producer breadth:** matrix-first implementation includes role/rating/reliability/League/amendment gaps now. Current related old tests asserting no role notifications must update intentionally with new contract; preserve unrelated self-leave/no-op exclusions. No automatic follow-up.
- **Rating replay/League snapshots:** emit only committed visible publication changes, stable source/snapshot identities, not intermediate calculations or snapshot reads. Test no-op rebuild and genuine changed publication separately; no ratings/standings arithmetic changes.
- **External duplicate window:** retry can follow provider success and lost acknowledgment. Persisted identity/fencing plus notification tag mitigate; document best-effort acceptance, never promise exactly-once OS delivery.
- **Workers transport/build:** worker preview encrypted-send compatibility gate precedes producer rollout. Preserve server-only import boundaries; node-only adapter tests not enough. Dependency fallback remains same unit/scope.
- **Scheduler/misconfiguration:** independent sweep execution, bounded claims/backoff, loud health/errors; dispatch kill switch does not erase in-app/job data. Missing credentials block live delivery verification, not mocked code completion. Queue retention bounded by TTL, no silent unlimited retries.
- **SW upgrades/offline:** waiting update confirmation and dirty-form deferral; never cache auth/SSR to simulate offline app. Forward deploy safe worker to repair bad cache policy; test old-to-new activation and duplicate controller events.
- **Rollout order:** additive schema/RPCs → compatible app/SW → configured keys → enable dispatch → real-device smoke. Keep dispatcher off during incomplete deployment; provision secrets outside tracked files. App rollback leaves additive data and authoritative alerts; service kill switch isolates external sends. Required disabled/broken production delivery is not full epic acceptance.
- **Unavailable verification:** Pencil MCP broken during planning and live-device credentials not verified. Caller owns unblocking; record evidence when available. If still blocked at release, report remaining AC/test rows honestly and request explicit scope decision; issue creation alone never satisfies them.
